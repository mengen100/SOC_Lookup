# Search discovery audit: 1 October 2026

## Evidence

Search Console exports cover performance through 28 September and indexing through 21 September. The last 28 days had 310 impressions and 1 click, compared with 868 impressions and 3 clicks in the preceding period. These are small samples. Improved average position can reflect a change in query composition, rather than a broad ranking recovery.

The indexing export reports 105 indexed pages, 13 discovered but not indexed pages, and 3 redirect URLs. The redirect URLs are the HTTP and www homepage variants; their exclusion is expected.

The 13 pending URLs are `/about/`, `/windows-events/`, `/tools/sigma-converter/`, Windows events 1102, 4657, 4732, 4765, 4779, 4794, and Sysmon events 9, 19, 21, 255.

## Production checks

- Existing `npm run verify:production -- https://soceventlookup.com` checks all passed.
- Sitemap contains 118 unique public page URLs.
- All 118 pages return HTTP 200 without a redirect and declare the expected canonical URL.
- No audited page declares noindex in HTML or the X-Robots-Tag header.
- All 118 pages are reachable from the homepage through anchors in server-rendered HTML, without executing JavaScript.
- Windows event index has inbound links from 117 other audited pages. Event 1102 has inbound links from 7 pages. These are not orphan pages.

Run the expanded read-only audit with Python 3 (standard library only):

```text
python scripts/audit-discovery.py https://soceventlookup.com
```

The audit uses four concurrent requests, prints all failures, and exits nonzero on fetch, canonical, noindex, or reachability failures. It does not test Googlebot firewall rules or guarantee indexing.

## Search Console actions

Live tests on `/windows-events/` and `/windows-events/1102/` passed on 1 October: crawl allowed, successful fetch, indexing allowed, and correct declared canonical. Event 1102 also had one valid Breadcrumbs item. The indexed-version reports said URL unknown to Google, unlike the older discovered-status summary. This discrepancy does not establish its cause.

Both URLs were submitted once for indexing. Google confirmed each was added to its priority crawl queue. A request is not proof of completed indexing.

The sitemap report initially displayed a last-read date of 15 July. After resubmitting the validated existing sitemap, Search Console displayed submission and last-read dates of 1 October, Success, and 118 discovered pages. No sitemap URL or website security setting was changed.

- [Windows PowerShell logging](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_logging?view=powershell-5.1) and [PowerShell instrumentation manifest](https://github.com/PowerShell/PowerShell/blob/master/src/PowerShell.Core.Instrumentation/PowerShell.Core.Instrumentation.man): configuration and T_ScriptBlock_Compiled payload fields. The manifest is a current upstream reference, not a guarantee about every installed Windows PowerShell build; confirm collected XML.
- [4769 documentation](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4769) and [Kerberos RC4 remediation](https://learn.microsoft.com/en-us/windows-server/security/kerberos/detect-remediate-rc4-kerberos): ServiceName, Status, normal option mask, encryption algorithms, and supported-type/key context. The RC4 remediation table explicitly distinguishes ticket algorithms from account bit flags.
- ATT&CK mappings remain [T1059.001](https://attack.mitre.org/techniques/T1059/001/), [T1110.001](https://attack.mitre.org/techniques/T1110/001/), [T1110.003](https://attack.mitre.org/techniques/T1110/003/), and [T1558.003](https://attack.mitre.org/techniques/T1558/003/). Process/path and request-volume conditions are contextual hunting guidance, not attributed vendor rules.
